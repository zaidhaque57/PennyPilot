
# PennyPilot — Personal Finance Tracker

PennyPilot is a full-stack personal finance tracking application designed to help users manage their income, expenses, and monthly budgets through a clean, responsive dashboard.

The project is built with React and TypeScript on the frontend, Java Spring Boot on the backend, and MongoDB for data storage. It includes user authentication, transaction management, financial summaries, and interactive visualizations.

## Features

- **User Authentication:** Register and log in securely.
- **Dashboard:** View financial summaries for a selected month.
- **Income Tracking:** Record and monitor income transactions.
- **Expense Tracking:** Add, view, and delete expense transactions.
- **Transaction Categories:** Organize transactions by category.
- **Monthly Financial Summary:** Review income, expenses, and balance.
- **Transaction History:** View transactions and their details.
- **Charts and Visualizations:** Understand financial activity through charts.
- **Calendar:** Select dates and organize transactions by day.
- **Responsive Interface:** Designed to work across desktop, tablet, and mobile screens.
- **Personalized Branding:** Custom PennyPilot logo and matching browser favicon.
- **REST API:** Frontend communicates with the Spring Boot backend.
- **MongoDB Integration:** Store user and financial data in MongoDB.

## Getting Started

### 1. Clone the Repository

Replace `YOUR_USERNAME` and `YOUR_REPOSITORY` with your actual GitHub username and repository name.

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
cd PennyPilot
```

Alternatively, if the repository has already been cloned, open the project folder in VS Code.

### 2. Configure the Backend

Open the backend directory:

```bash
cd backend
```

Create a `.env` file inside `backend/`:

```env
MONGODB_URI=your_mongodb_connection_string
JWT_SECRET=your_long_random_secret_key
```

Replace the example values with your own credentials. Never commit real secrets to GitHub.

The backend configuration should include the following properties, if they are not already present:

```properties
spring.config.import=optional:file:.env[.properties]
spring.application.name=pennypilot
server.port=8080
spring.data.mongodb.uri=${MONGODB_URI}
spring.data.mongodb.database=pennypilot
spring.data.mongodb.auto-index-creation=true
app.cors.allowed-origin=http://localhost:5173
app.jwt.secret=${JWT_SECRET}
app.jwt.expiration-ms=86400000
```

Start the backend from the `backend/` directory:

```bash
./mvnw spring-boot:run
```

On macOS or Linux, if the wrapper is not executable, run:

```bash
chmod +x mvnw
./mvnw spring-boot:run
```

The backend should be available at:

```text
http://localhost:8080
```

Health check:

```text
http://localhost:8080/api/health
```

### 3. Configure the Frontend

Open a **second terminal** and navigate to the frontend directory from the project root:

```bash
cd frontend
```

Create `frontend/.env`:

```env
VITE_API_BASE_URL=http://localhost:8080/api
```

Install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Open the URL printed by Vite, usually:

```text
http://localhost:5173
```

Keep both the backend and frontend running while developing.

## Environment Variables

| Variable | Location | Purpose |
|---|---|---|
| `MONGODB_URI` | `backend/.env` | MongoDB connection string |
| `JWT_SECRET` | `backend/.env` | Secret used for JWT signing |
| `VITE_API_BASE_URL` | `frontend/.env` | Backend API base URL |

**Security reminders:**

- Do not upload `.env` files to GitHub.
- Do not place database credentials or JWT secrets in frontend environment variables.
- Variables beginning with `VITE_` are exposed to the browser and must not contain secrets.
- Use strong, unique secrets and configure production environment variables through your hosting provider.

## API Overview

The frontend communicates with the backend using HTTP requests.

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | Check backend health |
| POST | `/api/auth/register` | Register a user |
| POST | `/api/auth/login` | Authenticate a user |
| GET | `/api/transactions` | Retrieve transactions |
| POST | `/api/transactions` | Create a transaction |
| DELETE | `/api/transactions/{id}` | Delete a transaction |
| GET | `/api/dashboard?month=YYYY-MM` | Retrieve a monthly dashboard summary |

Protected endpoints require valid authentication according to the backend security configuration.

*Note: This table documents the intended/currently used API paths. Verify request fields, response formats, and any additional endpoints against your actual backend implementation.*

## Troubleshooting

### Frontend cannot connect to the backend

- Confirm that Spring Boot is running on port `8080`.
- Check `frontend/.env`.
- Confirm `VITE_API_BASE_URL` is set to `http://localhost:8080/api`.
- Restart the Vite server after changing environment variables.

### MongoDB connection fails

- Check `MONGODB_URI` in `backend/.env`.
- Verify your MongoDB Atlas network access settings.
- Confirm the database user has the required permissions.
- Ensure the connection string is valid.

### JWT or authentication errors

- Verify that `JWT_SECRET` is configured in the backend.
- Restart Spring Boot after changing backend environment variables.
- Log in again if an existing token is expired or invalid.

### Port already in use

Another application may be using the required port. Stop that application or configure an available port and update the corresponding frontend API URL or CORS settings.

### Favicon does not update

- Confirm `frontend/public/favicon.svg` exists.
- Confirm `frontend/index.html` references `/favicon.svg`.
- Hard-refresh the browser using `Cmd + Shift + R` on macOS.

## Security

- Password handling should use a secure password encoder on the backend.
- Protected API routes should enforce authentication and authorization.
- JWT secrets and database credentials must remain private.
- Validate transaction amounts, dates, categories, and other user input on the server.
- Configure HTTPS and production CORS origins before deployment.
- Never commit access tokens or real credentials to version control.
